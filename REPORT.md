# REPORT

An LLM is the right tool for *discovering* an unfamiliar workflow and the wrong authority for *repeating* it. A model drives discovery behind a trusted execution boundary; a successful run is compiled into a typed, parameterized capability that names semantic controls rather than a transcript; and production replay executes it with no model in the decision loop, advancing only when observable postconditions hold.

## 1. Architecture

The load-bearing decision is a trust boundary between a probabilistic proposer and a deterministic executor. During discovery the model only emits a typed `ProposedAction`; it never touches the browser. Every proposal crosses one trusted path — `TrustedKernel` — that enforces navigation scope, control ownership, semantic target resolution, and software-derived risk before any side effect, then observes the result. This is *who is allowed to believe what*: the model may propose, but scope, risk, and success are decided by software.

A successful run is compiled (`src/computer_use/discovery/compiler.py`), not recorded, into a `Capability` — a normalized execution IR whose steps name semantic controls and whose inputs are symbolic. So the same run replays for a different member without re-embedding the discovery value, and a reviewer or calling agent reads a typed contract, not model prose. Replay (`src/computer_use/execution/session.py`) drives the *same* kernel with the model absent, so the reviewed authority path is identical across discovery and replay — only the proposer changes.

The target is `LegacyCore`, a synthetic credit-union workstation built as the hostile case the environment describes — an iframe workstation, dense non-semantic tables, no test IDs — so the abstractions are pressured, not flattered; it is the surface under test, not the architecture. The deliberate trade-off is single-process, synchronous execution rather than premature distributed infrastructure: the abstractions are shaped to scale, but building that now would draw effort from the load-bearing seams.

## 2. Artifact schema

The schema (`src/computer_use/model/artifact.py`, `src/computer_use/model/values.py`) captures reusable knowledge extracted from a run, not a recording of it. A `Capability` carries an id, an integer `version`, a vendor/application target, typed `inputs` and `outputs`, ordered `Step`s, and a `success_checkpoint`. Artifact models use `extra="forbid"` and validate closed: a reference to an undeclared output or an ill-formed condition fails to load rather than misbehaving at runtime.

Each `Step` is a typed action (click / type / extract) over a semantic `TargetDescriptor` — a role plus accessible name, a label, visible text, or a relational `table_cell` (`row_contains` / `column_header`) — with ordered `fallbacks` and an optional `frame` hint. Targeting is semantic because the environment has no stable selectors or test IDs; a recorded CSS path would be the brittle choice. The value a type step writes is a `ValueRef` with explicit provenance — `ParameterRef | SafeLiteral | SecretRef | DerivedValue` — so provenance is *created* at compile time, not inferred later from a coincidental scalar. A member id compiles to `ParameterRef(member_number)`, never the concrete value; a secret is a `SecretRef` only the trusted runtime resolves.

Success and outcomes are observable `Condition`s (text / heading / route pattern / declared-output presence), reused as a step postcondition, the capability checkpoint, and a business-outcome detector. Business outcomes are first-class — "no such member" is a `BusinessOutcome` rather than an error string, preserving the distinction the brief explicitly asks for. A single consequential write also carries a `MutationVerification` recipe (§3). The artifact is versioned and reviewable by a human and a calling agent alike; examples are in `evidence/capability/`.

## 3. Determinism & error handling

*Deterministic* here means deterministic control logic given observed external state, not a deterministic world. Replay makes zero model decisions — it runs with the discovery API key absent and reports `model_calls = 0` — deriving determinism from stable semantic resolution and observed verification, not replayed coordinates. Resolution requires exactly one match; more than one is `LOCATOR_AMBIGUOUS` and fails closed rather than choosing the higher-scoring candidate; zero triggers ordered fallbacks, then `TARGET_MISSING`. A classified transient (an execution-context race mid-navigation) is retried within a bounded budget; a genuine driver error is not. Progress counts only when an observable postcondition confirms the expected state — a returned click is not success.

Results are a discriminated `RunResult = Success | BusinessOutcome | Escalated | Failure`. Three map onto the brief's taxonomy — expected **business outcomes** the caller needs (`MEMBER_NOT_FOUND`), **recoverable conditions** (a bounded transient retry), and **hard failures** that stop with a debuggable but *sanitized* diagnostic (`CHECKPOINT_FAILED` names the observed heading; the observed field is a structural route pattern, never the concrete PII path). `Escalated` is deliberately a fourth outcome, not a recoverable condition: the state in which automation transfers authority to a human (§5).

The consequential write is the deepest case, and it strengthens the core loop rather than replacing it. A commit whose response is lost does **not** mean the write failed, and the runtime never blindly re-dispatches: it dispatches exactly once, then establishes truth through the read-only verification the model *discovered* — return to the member, re-derive the account list by the same parameter, read the effect — attributing a commit only as a baseline-absent → present transition. The outcome is `COMMITTED` (Success), `MUTATION_NOT_COMMITTED` (an absent effect on a read source the trusted environment marks authoritative), or `MUTATION_AMBIGUOUS` (escalation, never a guess); whether absence is authoritative is a runtime policy decision, never a flag in the artifact. These conditions are exercised deterministically: `LegacyCore` injects reproducible states — a not-found result, a permission denial, a session timeout, an unexpected dialog, and the commit-uncertainty family — that the same model-free runtime classifies into typed results. Captured runs are in `evidence/`.

## 4. Heterogeneity & multi-tenant

*(Design; one concrete surface is implemented.)* `PlaywrightSurface` already exercises the hostile legacy-web target — frames, table-based workflows, no test IDs — so legacy web is not hypothetical here. The portable boundary is semantic artifact intent above surface-specific perception and dispatch, expressed as the `Surface` protocol (`src/computer_use/surface/base.py`): the artifact speaks in roles, names, and table cells, not Playwright mechanics. A desktop or second-surface adapter would reimplement observation, resolution, and action over OS accessibility or automation while preserving those semantics; a web-only concept such as a route or frame constraint that an adapter cannot honor fails explicitly rather than degrading silently.

Reuse across tenants is a binding problem, not a copying problem. Many institutions run the same vendor product configured, branded, and versioned differently, so the design is one reviewed **base capability** plus small, validated per-tenant/version **binding overlays** that specialize only narrow target identity or layout — a renamed control, a relocated field — resolving to one deterministic effective descriptor at load. Bindings cannot rewrite workflow semantics; a genuine flow change is re-discovery producing a new immutable capability version. A production deployment would detect drift by aggregating per-run signals the replay path already emits — fallback use, `TARGET_MISSING` / `LOCATOR_AMBIGUOUS`, and checkpoint failures — routing to investigation → an updated binding or new version → deterministic validation → approval. The governing invariant: production replay never silently rewrites an approved capability or binding. Not built: a desktop adapter or tenant-routing control plane — neither requires reshaping the artifact.

## 5. Escalation & handoff

The system escalates rather than guesses, and the human works the *same* live session. Replay raises an intervention on a state it cannot classify — an unmodeled blocking dialog (`UNKNOWN_DIALOG`) or a mutation whose effect cannot be established (`MUTATION_AMBIGUOUS`) — and discovery raises one when the model itself proposes `request_human`. Either way a structured `InterventionRequest` carries the capability, step, and reason plus a deterministic Expected-vs-Observed view built from the compiled artifact and a fresh structural read — no model prose on the replay path.

Control ownership is a `ControlLease` with a monotonic epoch — the single source of truth for who may act. Automation pauses and is *fenced*: the kernel refuses to act unless it owns the lease at the current epoch, so work prepared under a superseded epoch is rejected after a takeover. The operator drives the same Playwright page and context through a terminal surface, acting by control id, and each human action is audited with sensitive values redacted. On hand-back the runtime reconciles current state before resuming; a paused mutation re-runs only its read-only verification and never re-dispatches the write. One control-transfer primitive serves both authorities — replay-runtime and discovery-model — which makes the handoff a real seam rather than two special cases. Completed handoffs are in `evidence/replay_handoff/`, `evidence/replay_mutation_handoff/`, and `evidence/discovery_handoff/`. A real-time co-browsing console is out of scope by the brief; the operator surface is intentionally minimal, but the control-transfer model is real.

## 6. Safety

Guardrails are enforced in trusted software, on the resolved control, before any effect. Navigation is constrained by a configured origin/route policy, and the caller-supplied target cannot define its own scope; enforcement is frame-aware, validating every framed document that carries an origin, so an in-scope top page cannot mask an out-of-scope workspace iframe — which matters because the real surface is iframe-based. The action vocabulary is a closed allowlist, and software-derived risk on the resolved target (never trusted from the artifact) decides what may execute: a consequential write needs a one-time human approval bound to the operation's fingerprint — action, resolved target, landmark, control epoch — consumed exactly once, so a forged or replayed grant fails closed; an irreversible action is never auto-approved; and verification steps are re-classified read-only at runtime, so a write cannot be smuggled into a "verification."

Regulated data is handled by construction. Invocation parameters are symbolic before model egress (`<param:member_number>`), secrets are withheld from the model, and observation candidates omit their cell text so rendered financial values are not sent to it. Evidence is allowlisted and sanitized *before* persistence, not scrubbed after: financial outputs masked (`<financial>`), member ids as route patterns, verification codes as `<redacted>`; where a rich visual signal cannot be shown safe, a structural snapshot is kept instead. The limits are explicit: the allowlist is origin/route/name-based and the safe-action rule keys on control names — fine for this surface, but needing richer operation context across many apps — and there is no OCR-based PII detection or desktop sandboxing. This is a bounded trusted runtime, not an absolute guarantee.

## 7. Cuts

The strategy was depth on the load-bearing seams — the artifact contract, deterministic replay with real error semantics, consequential-write correctness, and the handoff — and deliberate narrowness elsewhere.

- **Desktop / second concrete surface adapter** — Playwright already exercises the hostile legacy-web target; a desktop surface (accessibility tree / OS automation) sits behind the `Surface` seam until a real desktop core requires it.
- **Real-time co-browsing operator service** — the terminal handoff is real; a concurrent, remote, audited console is the productionization.
- **Multi-tenant routing / binding control plane** — the overlay and drift model are designed; the plane is only needed at hundreds-of-tenants scale.
- **Deeper hostile-table resolution** — a baseline `row_contains` / `column_header` resolver is built; virtualized or paginated grids, merged cells, and OCR are deferred until a surface demands them.
- **Automatic model fallback on replay failure** — omitted because it would change the deterministic replay contract; a future bounded fallback would be explicitly policy-gated, evidence-producing, and separate from normal replay.
- **Multi-run stability scoring** — not built; a cheap next step.

These cuts preserve depth in the load-bearing execution and safety seams while leaving scaling and additional surfaces behind explicit boundaries.
